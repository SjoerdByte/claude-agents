TEST 5: S3 UPLOAD ENDPOINT
================================================================================

--- 5a. POST /v1/upload/anthony/test (empty body) ---
Request:  curl -sS -X POST --cacert /root/.ccr/ca-bundle.crt "https://web-api-staging.deblock.com/v1/upload/anthony/test"
Response: {"status":"ok"}
HTTP Status: 200

--- 5b. POST /v1/upload/anthony/test (multipart/form-data) ---
Request:  curl -sS -X POST -H "Content-Type: multipart/form-data" --cacert /root/.ccr/ca-bundle.crt "https://web-api-staging.deblock.com/v1/upload/anthony/test"
Response: {"status":"ok"}
HTTP Status: 200

FINDING [HIGH - POTENTIAL]: The upload endpoint returns HTTP 200 {"status":"ok"}
with NO authentication required. Both an empty-body POST and a multipart POST
succeed. Key concerns:
  - No authentication or authorization check is performed
  - The endpoint accepts requests with any username path parameter ("anthony")
  - Returns success even with an empty body (no file)
  - Does NOT reveal S3 bucket names in the response
  - The "ok" response may indicate the endpoint silently succeeds or does nothing
    when no file is provided, but the lack of auth is the primary concern
  - An attacker could potentially upload arbitrary files to the S3 bucket associated
    with any user path segment

RECOMMENDATION: Add authentication. Validate the user path parameter against the
authenticated user. Require a file in the request body. Rate limit this endpoint.
